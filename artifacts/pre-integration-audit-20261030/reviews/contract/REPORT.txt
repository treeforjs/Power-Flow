Findings requiring disposition before joint execution
-----------------------------------------------------
F1 HIGH: a legacy compound entry point can reach native Poisson in full-time mode.
  native/source/src/mfem_pic_arena.cpp:1334-1358 admits compound_impl without
  refusing full_time_boundary_. An empty builder satisfies its ordinary checks;
  line 1424 then calls stage. stage:711-712 calls solve_fields when fields_current
  is false. Full-time genesis deliberately makes that flag false and clears
  native potential (mfem_pic_full_time.inc:899-902). Thus prepare()/transport's
  direct full-time refusals do not close the legacy compound route. Even a
  no-event legacy compound can invoke the forbidden operator. The selected root
  coordinator uses CollisionScope and does not call this route, but public mode
  separation and the intended legacy-refusal test are incomplete.
  Remedy: reject full-time mode at every legacy compound/stage entrance before
  callback or native mutation; retain zero-call linker traps for all old entry
  points, including no-op compounds. This is static call-path evidence; the
  forbidden solve was not invoked here.

F2 HIGH: common preflight does not bind mutable proposed field/heat to native seals.
  parent/source/closed_parent_joint_step.hpp:15-20 exposes the mutable
  field_heat proposal. Lines89-110 seal hashes of its then-current field/heat in
  the native token. Common preflight:122-130 subsequently checks accepted source,
  native token, parent RNG and Hall preflight. Hall axial_joint_v2.hpp:72-76
  checks accepted field/heat, saved census, and thermal token ownership, but not
  proposed field values, endpoint time/revision, or proposed heat-state hash
  against the native token's immutable boundary audit.
  Example consequence: after successful prepare, changing
  trial.field_heat->field.time_s (or a field coefficient) leaves those preflight
  predicates unchanged. Publication can install that changed field while the
  native boundary retains the previously sealed hash/time. This is a direct
  source-level counterexample; no actual joint proposal was executed to exhibit
  it. The corrected Hall caller has the same preflight gap.
  Remedy: make the publishable proposal immutable, or preflight recomputed
  proposed field/heat hashes and endpoint clocks against the immutable native
  token's boundary audit, plus motion midpoint identity. Keep the no-throw swap
  barrier. Add deliberate proposal-mutation refusals with all owners unchanged.

F3 HIGH at the native primitive boundary: starting/cross-slot/final RNG seals
  are not independently enforced by intermediate-001.
  mfem_pic_full_time.inc:154-171 checks each explicit half-exposure and its
  completion metadata. completion_validate (arena.cpp:1473-1504) checks a prior
  completion for the SAME owner if present; initial stage 0 accepts any digest.
  The native first exposure does not require its before_rng_clock hash to equal
  accepted boundary.rng_sha256. The second exposure need not select the same
  completion owner as first, and seal:737-764 only requires a digest for the
  final rng_sha256, rather than equality with the second actual completion.
  Closed ParentSubflow currently supplies stronger checks at :385-475, and the
  coordinator passes its staged second RNG hash. That caller is consistent,
  but native admission/restore alone does not establish the advertised chain.
  Remedy: enforce initial accepted RNG, same integration owner, consecutive
  exposure sequence, first-after/second-before, and final-second-after natively;
  retain ParentSubflow's opaque exposure-key checks as an independent barrier.

  Hall axial_joint_v2.hpp:44-46 computes .5*(accepted.E+proposed.E) and analogous

F10 MEDIUM: full-time restart caps input bytes before DOM parsing, but collection
