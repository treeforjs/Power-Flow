Gas target owner and conservative native interface
-------------------------------------------------
gas-target-owner-v1-20261101 contains actively written CPU/device source,
an object file and a new test harness, with no completed test/receipt/seal found.
Its useful approach is a correction ledger on top of native neutral carriers:
for consuming reactions, subtract sampled target K/P and add the actually
removed native packet K/P back to that correction ledger. Native performs the
count debit once. Combined native-plus-owner moments then lose the sampled
target used by event kinematics. For GAS return, no count debit is permitted;
the correction is outgoing minus sampled incoming target K/P.

Concrete blockers in this in-progress implementation:
* gas_core.h:552--574 silently clamps negative corrected thermal variance to
  zero and ignores nonzero correction when population N<=0. Exact signed
  bookkeeping does not make the resulting target distribution realizable.
  Refuse unrealizable moments, handle zero-count residual ownership, and use
  the same kinetic/momentum convention as the actual target sampler.
* gas_owner.cpp:516--527 checks stage is 1 or 2 but not order/uniqueness;
  repeated take(stage) double-books data. commit():635--662 does not require
  completed ordered stages. feedback():567--572 ignores stage.
* Header claims of CPU/device identity and production presets are not test
  evidence. Keep native's current fail-closed target-energy guard.
