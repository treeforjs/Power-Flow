   checkpoint schema hall-v3.4-resident-checkpoint-v1).
 - Resident Models: backend descriptor hall-v3.4-resident-field-descriptor-v1 (new kernels, v7.1 forms core, residual
   rule hall-v3.4-independent-residual-v1: exact sum of squares instead of the x87 sequential norm), block-Merkle state
   digest hall-v3.4-field-state-merkle-v1 (+ divb_gross array).
 - Native v7.1 lane configuration only (field_digest_form = blocks_v71): the record's trial_field_sha256 and
   current_A_m_sha256 in the API-071 block forms, hence a different record v7 digest for the same motion.
 - Unchanged (bit for bit, both host-work modes): deposit support values (x87 emulated exactly, no identity change),
   census v2, record v7 in the streaming form, K, W, work scales, sinks/births records, motion and field arithmetic, refusal
   texts and points, heat and kinetic-ledger digests.

9. Remaining host work of the Hall coupled step (device path) and why
 O(1) + O(sinks + newborns) per step, plus:
  - host census input (native v7 only): one gather pass, 80 bytes per row (memcpy + ID order + text lengths); none with
    the native v7.1 device census (lane bench: census CPU LANE_CENSUS at 1e6);
  - host record arrays (native v7 only): endpoint/path download and memcpy (O(N) bytes); none in the lane;
  - O(mesh) once per step: the streaming trial-field digest (native v7; the block form is device-computed for v7.1), the
    endpoint and initial charge digests of the record header (motion-array-binary64-v1, O(nodes); API-007 defines no
    block form for them), the current's streaming digest (native v7 only), the host-midpoint digest at preflight (host
    record arrays only);
  - the thermal owner (ThermalV3, host-resident: conductivity and Joule power of the metal cells, O(metal cells));
  - block-Merkle roots of the device state leaves (O(mesh/256)) and a 16-leaf host sample per digest.

 10.1 Native v7.1 defect (candidate007.1, source/src/mfem_pic_full_time.inc, motion_v7_dispatch, device_verified
      branch): `const auto &hr = r.device.present() ? *host_record(r, dev, keep) : r;` binds a reference to the record
      owned by the temporary shared_ptr returned by host_record, which is destroyed at the end of that statement; the
      host path then reads a dangling record. With Hall's device-only record (no host spans) the host path refused with
      "unrecognized motion record schema" (coordinator-v7.1-copy/r6-verified-n10000-200um). The host-mode branch holds the
      temporary for the duration of the call and works. Fix on the native side: keep the shared_ptr in a named variable.
      Qualification here used device mode vs host mode on the same records instead (section 6.2).

11. Decisions taken (engineering; approved decisions D1-D3 in README 4a)
 - Deposit support on the device by exact emulation of the sealed x87 builder (64-bit significand, nearest even; 192-bit
   window add/sub, exact 128-bit product, sealed carrier order per node): no identity change; the approved exact-sum
   alternative with an identity change was not needed.
 - Device-path waits: blocking stream synchronise instead of the busy-waiting event waits (no value changes).
 - Trial-field digest of the binding computed once per step for the accepted iterate (same value; the earlier iterates
   are discarded and the fixed point leaves the trial buffers unchanged).
 - Hall v3.4 builds against the native v7.1 forms library (v7 forms unchanged plus the block forms); the NVRTC kernels
   embed the v7.1 forms core (same digests).
 - Native v7.1 lane: Hall recomputes its own census v2 from native's device rows (independent of native's census digest);
   the census state table is the registered states, ascending, checked against the device census's states digest
   every step; the endpoint and initial charge digests of the record header stay streaming (no block form defined).
 - Coordinator copy: one hall_gpu Session/primitives/forms implementation in the v7.1 build (the native v7.1 library's
   objects, same sources as Hall's); the v7 build keeps its own objects; the T1-T7 parity comparator classifies the
   genesis max_divB_T_m change as the documented divB change (finite, nonnegative, not larger) instead of a mismatch.
 - Native lane qualification by device mode vs host mode on the same records (native v7.1 device_verified mode is
   unusable with device-only records: 10.1).
 - Bench lane mode: the test uploads the census to the device before each step (untimed), standing in for native's
   device census.
 - Test fixture fixes: the resealing helpers of test_v32 (host and resident checkpoints) now include the divB gross
   ledger in the state digest they reseal; test_resident parity-vacuum compares the solve record of the host reference
   backends (v3.3 norm rule) with the resident backend (v3.4 rule, D1) as: iterations bitwise, rhs norm and residual
   within the summation rounding |a - b| <= (n 2^-64 + 2^-51) max(a, b).
