# Complexity and measured opportunity

The baseline's 422 inferred solve spans contain 2.864 s of device activity in 3.318 s of host time, approximately 86.3% coverage. Actual application vector transfers take only 67.193 ms. Sparse triangular and TRSV kernels account for most device time. Across the wider trace, long host gaps separate solves. Evidence is preserved in [trace-review.md](/home/treefor/sim-workspace/powerflow/outputs/pic-profile/gpu-independent-review/trace-review.md).

If operation durations remain fixed, removing every non-device interval inside those backend spans offers about 0.454 s of schedule-only headroom in this traced replay. This is an optimistic trace-specific ceiling, not an actual graph gain or an unprofiled application prediction. Capture adds a reference solve per system, graph construction/inspection, pinned buffers, staging copies, stream/allocator lifetime obligations and unsupported-feature recovery. V2 adds a setup-only synchronization and diagnostic state bookkeeping; no file I/O is added to steady successful solves.

The additional record code is isolated from CUDA so its multi-solver and failure semantics can be tested without GPU access or new dependencies. Source changes in the main program are limited to diagnostic begin/complete/failure hooks. Numerical equations, particle stepping, conservation thresholds, ABI structs and two-refinement behavior remain unchanged.

These fixes make the experiment reviewable; they do not justify adopting graphs. Keep the default off. Require the actual 130,321-node checkpoint replay, both solver instances, finite-value/field/history/ledger/particle comparisons, unchanged scientific guards and repeated unprofiled required-mode application timings. Include first-RHS warmup/capture cost and staging, and measure off mode in the same v2 binary to isolate implementation overhead. Compare medians and spread across interleaved repetitions under agreed allocations; do not infer a win from one short receipt or a solve timer alone.

If capture is unsupported, correctness is unstable, or total wall-time gain does not exceed repeat variability by a useful margin, the graph complexity is not justified by this baseline. Host-side hot paths remain the larger measured opportunity. Auto fallback remains experimental because this change does not prove cuDSS 0.6 opaque state survives all failed captures. Required mode and a successful outer receipt remain mandatory for acceptance. No deployment, GPU execution or new benchmark was performed here.
