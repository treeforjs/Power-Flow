Opaque holder, moves and getters
--------------------------------
ClosedParentTrial:16-44 has a private constructor, no public copy, and private
unique ownership of native/private-step/field-heat state, random token, census,
source seal and expected step. Only the three narrow coordinator functions are
friends. There is no ordinary public mutable candidate/token/vector getter.

Default move transfers the unique_ptrs, leaving the ordinary moved-from holder's
native and field_heat pointers null. can_publish:146 checks those before any
dereference, so the ordinary moved-from path should refuse. A published holder
has consumed=true (:159); native/parent tokens are also consumed. Moving a used
holder copies that true flag, and cannot revive its native publication status.
The source's false consumed flag after an ordinary prepublication move is not a
reuse path because its unique_ptrs are null. Move assignment discards only the
destination's unaccepted private proposal under the intended owner destructors;
it does not itself call publication. Self-move and token/owner destruction still
need actual runtime coverage. Compile-time traits alone do not prove those
effects or stale/foreign/double publication refusal.

audit():43 returns only a borrowed const JSON reference. The audit initializer
:134-139 copies diagnostic JSON, not native/Hall token pointers. The supplied
JSON implementation deep-copies objects/arrays/strings. Even editing diagnostic
JSON through a cast would not change the private expected step or owner token;
it could falsify diagnostics, so diagnostic bytes must never be an authority
factory. A retained audit reference is invalidated by holder destruction/move
assignment like any borrowed member reference. No ordinary authority leakage
through this getter was found. The pending JSON-motion replacement is a
separate authority boundary; serialized audits must not become its substitute.
